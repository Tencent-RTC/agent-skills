# 测试账号与体验消息

## 适用范围

用户希望真实体验会话、好友、群和消息时才进入。没有会话不一定是集成失败；先核对登录和加载结果，解释需要真实账号之间发生消息。

参考 Android Skill 的预览后执行方式，但本独立 Skill 不内置凭据、不自动调用 REST、不依赖某个固定 MCP。不把本地数组假数据说成服务器已生成。

## 操作前提

1. 确定客户实际用于体验的 Chat userID、SDKAppID、数据中心区域与测试应用。变量名不能当作运行时用户 ID。
2. 按 [凭据指南](../shared/credentials.md) 区分管理员REST权限与客户端登录用户签名，处理签名校验和目标账号注册；这里不重复实现签名或用权限错误试探签名有效性。
3. 有自有登录账号时以该账号为中心准备测试伙伴与专属群；不能只为 demo_alice/demo_bob 发消息然后宣称客户自己的账号能看到。
4. 没有可用账号时先明确将使用哪个测试账号登录，再准备双方 UserSig。默认名字只作示例，不能强制替换客户账号。
5. 告知重复执行可能新增重复消息，好友和群属于真实远端数据，可能产生计费和影响现有账号。

## 两条执行路径

### 集合中已有经过审查的工具

发现相邻 Android Skill 的 `scripts/seed_demo_data.py`（或其他等价实现）时，先读取脚本和其匹配版本的说明；不要仅凭本 Skill 引用就执行。Android 1.1.2 的工具提供 `--self-test`、默认预览和 `--apply`，支持 `--current-user`，但使用时仍核对实际参数及预览是否零网络写入。

- 先运行本地 self-test，再预览应用、参与账号、好友方向、群主与成员、发送方向。
- 将预览转成用户可理解的清单，取得本次真实创建/发送授权。
- 用同一计划执行 apply；任何错误停止并保留步骤与 ErrorCode/ErrorInfo，脱敏日志。
- 不自动安装或升级整个 skills 集合；不将为阅读脚本的权限当作远端写入授权。

### 单独安装、没有已审核工具

提供客户现有服务端/控制台的操作清单，或在用户明确要求后单独实现并验证 REST 工具；不声称脚本存在，不发明远端工具名，不临时生成管理员签名后自动发送。

[导入账号](https://cloud.tencent.com/document/product/269/4919)、[查询账号](https://cloud.tencent.com/document/product/269/38417)、[导入好友](https://cloud.tencent.com/document/product/269/8301)、[创建群组](https://cloud.tencent.com/document/product/269/1615)、[单聊消息](https://cloud.tencent.com/document/product/269/2282)、[群消息](https://cloud.tencent.com/document/product/269/1629) 的参数以当前官方接口为准。

## 验收

- 中心账号和伙伴属于同一应用且已导入；好友关系和群成员符合用户批准的方向。
- API 成功返回并能查询到对应消息；不能仅靠控制台文本输出。
- 客户以已确定的实际账号登录，可看到目标会话；UI 和服务端两侧证据分别说明。
- 完成报告只给脱敏后的目标、成功/失败步骤和下一步，不输出完整签名、SecretKey 或个人信息。
