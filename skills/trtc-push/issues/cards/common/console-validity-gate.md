# 控制台有效性门控（推送服务 + 通道证书）

## 与 MCP 的关系

本文件是 **知识卡**，不拥有独立主链。

- ROUTER `workflow_id`：`troubleshoot-*（各平台）`
- 关联 flow：`对应平台 offline-not-received / 跨端 flow`
- 挂载：MCP `stage-1-console-validity`
- 执行仍走 MCP 状态机；命中本卡后按挂载阶段取证，禁止用本卡替代 `complete_workflow_step`。

## 适用现象

用户反馈「离线推送收不到 / 不达」，尚未排除控制台侧失效时，**必须先过本卡**。

各平台 `offline-not-received` 主链第 1 步、跨端排障下钻原生前，均引用本卡。

## 步骤类型

本卡是 **校验提醒**，不是配置采集：

- 带控制台路径让用户核对。
- 默认用户可能不懂字段含义。
- 用户回 **通过 / 不通过 / 不确定**（可附截图），不要一上来索要证书 ID 原文。

## 必须提醒用户校验的两项

**套餐有效期 ≠ 推送证书有效期，两项都要核。**

### 1a 推送服务

- **怎么做**：腾讯云控制台 → **即时通信 IM** > **推送服务 Push** > **概览** > **选择 SDKAppID** > **查看服务状态**。
- **期望看到**：Push 服务已开通；体验版或套餐**未到期**。
- **回什么**：有效 / 未开通或已到期 / 不确定。

未开通或已到期时：先开通 / 续期，再排客户端配置；勿先改工程。

### 1b 通道证书

按问题平台提醒用户核对（一次控制台访问可与 1a 同轮）：

**公共路径**：腾讯云控制台 → **即时通信 IM** > **推送服务 Push** > **推送设置** > **选择 SDKAppID** > **厂商配置** > 按平台进入查看证书。

| 平台 | 怎么做 | 期望看到 |
|------|--------|----------|
| iOS | 厂商配置 > **iOS**，查看 APNs 证书 | 证书已配置；状态正常；有过期时间则**未过期**。P8 还需 Key 可用（未撤销）。 |
| Android | 厂商配置 > **Android**，查看问题品牌厂商证书 | 该厂商证书已添加且状态正常；若有过期/失效提示则未过期。 |
| HarmonyOS | 厂商配置 > **HarmonyOS**，查看鸿蒙推送证书；并核对 AGC 签名证/Profile | 鸿蒙推送证已配；签名证/Profile **未过期**。 |

- **回什么**：有效 / 无效或过期 / 不确定。

## 与后续步骤的边界

本卡**不**替代：

- Bundle ID / businessID / 开发生产对齐（主链第 3 步配置校验）。
- 包名 / 指纹等厂商细节（可下钻 `vendor-not-received` 等）。

展示异常（已确认送达但不弹）：建议仍做 **1a**；**1b** 仅在未确认送达时强制。

## 验证信号

- 1a、1b 用户结论均为「有效」，或已完成开通/续期/更新证书后再复测。
