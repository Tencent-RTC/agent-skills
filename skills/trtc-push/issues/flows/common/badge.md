# 角标 / Badge 显示、清除和厂商差异排查流程

## 与 MCP 的关系

本文件 **无独立 MCP workflow**（ROUTER 未挂 `workflow_id`）。

- 定位：无独立 workflow；运行时收不到时先按平台进 troubleshoot-*，角标再下钻本 flow
- 若同时存在「收不到 / 注册失败」等端侧运行时问题，先按平台进入对应 `troubleshoot-*`，再视需要回本文件。

## 入口现象

用户反馈通知角标不显示、角标不清零、角标数字不符合预期、希望设置角标图片，或不同厂商
角标表现不一致。

角标问题高频但不是同一根因。它可能是产品能力边界、厂商系统限制、payload 参数、客户端
清零逻辑或 iOS / Android 差异。

## 首轮证据

- 平台和厂商：iOS / Huawei / Honor / OPPO / vivo / Xiaomi / 魅族 / FCM 等。
- 期望能力：显示数字、红点、图片、自定义、点击清零、打开 App 清零。
- 推送 payload：`BadgeMode`、`BadgeAddNum`、APNs badge、厂商 badge 字段。
- 通知是否实际展示。
- 客户端是否实现清零逻辑。
- 系统桌面是否支持对应角标能力。

## 排查顺序

1. 先确认目标平台 / 厂商是否支持该角标能力。官网《自定义角标》「厂商通道支持说明」：iOS、华为、荣耀支持自定义角标；小米、vivo「跟随系统」（默认展示通知栏内属于该应用的通知数，不支持自定义）；OPPO、魅族「跟随系统」（支持红点，不支持自定义）；FCM 跟随系统、不支持自定义。
2. 确认用户期望的是数字、红点、图片还是清零。
3. 检查服务端 payload 是否携带正确 badge 参数。
4. iOS 检查 APNs badge 字段和客户端清零逻辑（打开 App 后角标清零需客户端调用系统 API）；iOS 默认把所有会话未读数之和作为角标，与 IM 未读数不一致时见下方分支。
5. Android 按上表的厂商支持情况确认；不同厂商角标策略不同（部分跟随通知栏、部分需单独申请权益），以各厂商规则为准。
6. 如果厂商不支持，按能力边界答复，不继续要求用户改配置。

## 分支处理

| 分支 | 判断信号 | 处理动作 |
|---|---|---|
| 产品 / 厂商不支持 | 小米、vivo、OPPO、魅族、FCM 要求自定义角标（官网《自定义角标》：这些厂商跟随系统） | 明确能力边界（厂商系统本身不支持的属产品边界，无法通过配置绕过），给替代方案 |
| payload 配置错误 | `BadgeMode` / `BadgeAddNum` / APNs badge 缺失 | 修正服务端参数 |
| 客户端未清零 | 点击或打开 App 后角标仍在 | iOS：客户端调用系统 API 清零；Android：业务按官网《自定义角标》的接口清理或更新角标数（华为不会因打开应用、点击或清理通知而自动清零） |
| iOS 角标与 IM 未读数不一致 | iOS 桌面角标不等于预期的未读数 | iOS 默认角标是所有会话未读数之和；需自定义时实现 `onSetAPPUnreadCount` 回调并返回自己计算的角标总数，见官网《自定义角标》 |
| 厂商系统行为 | 小米 / vivo 跟随通知栏数量；OPPO / 魅族只支持红点 | 按厂商规则解释 |
| 通知未展示 | 角标依赖通知展示 | 先排查通知是否展示 |

## 验证信号

- 支持角标的厂商上，payload 修正后角标按预期变化。
- 客户端清零逻辑执行后，桌面角标消失或归零。
- 不支持场景能给出明确边界和替代方案。

## 何时升级 / 转交

- 厂商公开文档未说明角标行为。
- 同一系统版本不同设备表现不一致。
- 需要厂商确认桌面角标能力或审核权益。
